Product Design · Fintech

User Recertifications

I worked as the principal UX designer on ZILO Invest: a digital investment portal for asset managers and financial institutions. As part of this work I designed a sophisticated UX pattern that aimed to streamline and simplify a complex compliance workflow.

Role
Lead Product Designer
Platform
ZILO Invest
Design system
ZILO Design System
Deliverables
Desktop + mobile flows

01 — The challenge

Every user certified, every cycle

On ZILO Invest, a new compliance feature needed to be implemented that ensured every user on a team was certified. It would also require a recurring cycle of verification to ensure they remained properly certified to remain on these teams.

This was important to get right, as this wasn't simply a matter of creating an efficient solution for the admins but also one of preventing serious security breaches. There was no existing feature to base this on, so I set out to identify the scope and place of this feature on the portal.

02 — Research

Grounding decisions in real admin behaviour

I started by aligning with stakeholders on business and security requirements, then interviewed admins who had managed similar certification processes at scale.

A stakeholder workshop consolidated findings into a shared understanding: admins need speed but the platform needed to be secure. This became a central part of the design brief.

I then conducted competitor research, with the help of tools such as Mobbin, to help me find examples of existing solutions to similar workflows as well as best practice UX patterns relevant to this design.

Deliberate actions

Bulk actions were essential due to the size of users potentially being dealt with at one time, but each user still needed an individual decision to ensure it had been authorised by an admin.

Visibility

Admins needed to be able to be made aware of any users who were approaching the recertification due date, but in a way that wasn't disruptive to their workflow.

Roles and clients

It was identified that during this process an admin would need to be aware of the roles and clients associated with that user, as these would be reviewed at that same time and would aid their decision making.

Removal

There would need to be a way to deal with users who were not to be recertified. In addition there would likely be a need for a way to edit the user's roles and clients without disrupting the flow of bulk recertification.

03 — Designing & testing

Iterations that shaped the final flow

This design process involved an enormous amount of iteration between initial ideation and testing, especially around the exact way the radio buttons would work.

User management

User management was identified as the place which made the most sense to place the entry points to this flow. I then redesigned user management in order to provide the entry points to recertification, and at the same time provide visibility of the recertification process. Created a new component called overview indicators, also introduced badges in user rows that correspond with the status.

Before After

Modal over drawer

The existing drawer pattern couldn't accommodate a task this complex. A centred modal keeps focus on the review while preserving context of the user management page behind it. A new design for a modal template had to be created and added to the design system.

Radio buttons

There were many iterations of the method the admin would actually use to recertify their users. Remembering that each individual user needed a deliberate action, these iterations included explorations with checkboxes, button labels, decisions on if a radio button should be preselected, ways to make the buttons visible and obvious to the user that they needed an action.

Single and bulk recertify

After realising the admin would enter a recertification view two ways (single view and bulk recertification) the design was updated to ensure the pattern was as similar as possible between these two views in order to prevent user confusion.

Toasts

Toasts were introduced to help the user with feedback with the somewhat complicated actions they were undertaking. These were not present in the design system at the time, so they were a whole new component I designed from scratch and added to the component library.

Skip vs Review later

There were also many iterations in the scenario an admin didn't have the ability to make a decision on a user straight away. Through testing and design iterations the solution became that the user needed to deliberately select a radio button, and that button was to be labelled "review later", as "skip" simply wasn't clear enough. The user would then be marked as skipped but still needing a decision in user management.

Skip with a note

There was an exploration that didn't make its way into the original design to skip with a note, which would allow an admin to leave a reason for skipping the user which could be reviewed by other admins. It was added to the backlog for future versions.

Responsive design

The entire project was done with responsive design as a priority.

04 — Outcome

Compliance that admins can actually run

The recertification feature shipped as a core part of the ZILO Invest admin experience. What started as a net-new compliance requirement became a set of reusable patterns: overview indicators, modal templates, toasts, and status badges that the platform continues to build on.

Admins can now see who needs attention before they open a review, work through users individually or in bulk with the same familiar card pattern, and get clear feedback on every action. The research and testing-heavy process meant those patterns were earned in realistic review scenarios, not just walkthroughs.

Visible from user management

Overview indicators and row-level status badges put recertification front and centre where admins already manage people, without pulling them into a separate compliance area.

Deliberate at any scale

Whether reviewing one user or a full page, every account requires an explicit decision. Bulk recertification stays fast without sacrificing the audit trail compliance demands.

Design system grew

Modals, toasts, and overview indicators introduced through this project are now reusable components across the ZILO Design System, including undo feedback on role removal.

Tested, then shipped

Iterations from moderated sessions (radio button validation, Review later, toast placement, single vs bulk parity) landed because admins used them under time pressure, not just in prototypes.
